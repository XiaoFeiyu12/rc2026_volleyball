## Cpp代码规范

### 格式规范
这部分无需担心，因为会有配套的vscode配置设置帮助管理、编写

#### 大括号
大括号表示<u>独立的作用域</u>，大括号的使用不应随意省略，以保证代码的规范性  
个人所见还是要**换行**，使其可以完全配合代码纵向的辅助细线，以保证可读性。  

*示例*：
```cpp
if (armors.empty())
{
    return false;
}
```
```cpp
for (const auto &armor : armors)
{
    if (armor.confidence > confidence_threshold_)
    {
        targets.push_back(armor);
    }
}
```
```cpp
while (!targets.empty())
{
    auto target = targets.front();
    targets.pop();
    tracker.track(target);
}
```
```cpp
namespace auto_aim
{
class Tracker
{
public:
    void init(const TrackerConfig &cfg);
    void track(const Armor &armor);
};
}  // namespace auto_aim
```

#### 缩进
缩进**只能使用`Tab`键**，禁止使用**空格**  
- 以下代码块要缩进:
    >`if`  
    `else`  
    `else if`  
    `for`  
    `while`  
    `do{}while()`  
    `class`  
    `struct`  
    >

*以冒泡排序为例：*
```cpp
void bubble_sort(std::vector<int> &arr)
{
	int n = arr.size();
	for (int i = 0; i < n - 1; i++)
	{
		for (int j = 0; j < n - 1 - i; j++)
		{
			if (arr[j] > arr[j + 1])
			{
				int temp = arr[j];
				arr[j] = arr[j + 1];
				arr[j + 1] = temp;
			}
		}
	}
}
```

- 以下标识不能缩进：
  >`private:`
  `protected:`
  `public:`
  `case:`
  >
  *以大家常见的新开命名空间、类、创建私有公有成员方法为例：*
```cpp
namespace auto_aim
{
class Detector
{
public:
	void detect(const cv::Mat &src, std::vector<Armor> &dst);

private:
	void preprocess(const cv::Mat &src, cv::Mat &dst);
	void find_lights(const cv::Mat &src, std::vector<Light> &lights);
	void match_lights(const std::vector<Light> &lights, std::vector<Armor> &armors);

	int min_light_area_;
	double color_threshold_;
	DetectCfg detect_cfg_;
};
}  // namespace auto_aim
```

#### 空行
这里是建议性规范，在子模块各步骤之间插入空行以及注释可使得代码可读性更高，以及函数实现上
*示例*
```cpp
void Detector::detect(const cv::Mat &src, std::vector<Armor> &dst)
{
	// 图像二值化
	cv::Mat binary;
	preprocess(src, binary);

	// 找到所有灯
	std::vector<Light> lights;
	find_lights(binary, lights);

	// 匹配灯
	match_lights(lights, dst);
}
```

#### 空格
这里遵循`Google`代码规范，主要是体现在以下方面
- 变量声明、赋值、运算
  ```cpp
  double angle = 0.0;
  int lost_cnt = 0;
  bool is_tracking = (lost_cnt < max_lost_) && (angle > angle_threshold_);
  double distance = std::sqrt(dx * dx + dy * dy);
  ```
- 多变量函数声明、调用
  ```cpp
  void solve_pnp(const std::vector<cv::Point3f> &object_points, const std::vector<cv::Point2f> &image_points,
                 const cv::Mat &camera_matrix, cv::Mat &rvec, cv::Mat &tvec);
  
  solve_pnp(object_points, image_points, camera_matrix, rvec, tvec);
  ```
- 高维vector
  ```cpp
  std::vector<std::vector<cv::Point2f>> contours;
  std::vector<std::vector<std::vector<double>>> feature_maps;
  ```
- 头文件include后面
  ```cpp
  #include <Eigen/Dense>
  #include <opencv2/opencv.hpp>
  #include <vector>
  
  #include "armor.h"
  #include "detector.h"
  ```

#### 指针星号*
这个网上众说纷纭哈，放前面更强调指针类型，但缺点是如果哪天你想声明多个指针时，比如
```cpp
int* a, b, c;
```
你可能会以为这三都是`int*`，实际上只有`a`是
为了减少这种错误，还是要求放在后面靠近变量  
*示例*：  
```cpp
int *a, *b, *c;
```
不过一般这样子还不如分开声明。  
此外包括引用符号`&`同理

#### Eigen矩阵初始化
项目大量使用Eigen库，其逗号初始化使用`<<`按矩阵行列填充数值。格式化工具（如clang-format）无法识别矩阵语义，会将矩阵排版拍平成一行。因此必须使用格式化开关保护：
- 每个`<<`初始化块前后分别加上`// clang-format off`和`// clang-format on`
- 每行数值对应矩阵的一行，逗号对齐
- 行向量可写在同一行

*示例*：
```cpp
// 4×4 变换矩阵
Eigen::Matrix4d T;
// clang-format off
T << 1, 0, 0, tx,
     0, 1, 0, ty,
     0, 0, 1, tz,
     0, 0, 0, 1;
// clang-format on

// 行向量可以一行写完
Eigen::Vector3d gravity;
// clang-format off
gravity << 0, 0, -9.81;
// clang-format on
```

### 命名规范
这里有个总原则，除去诸如`src` `dst` `cfg` `sys` 这类常规缩写、易辨识缩写外，尽量使用**英文单词**组合，~~如果不知道英文就去查词典~~，不要使用`a` `b`这种简单字母组合，以减少歧义并增加可读性。如果是简单循环可使用`i` `j`，此时循环嵌套不超过两层。  
很多时候你可能会忘了这些命名规范，但重点是要让别人能一眼能看出来你这个变量是参与哪个环节、在做什么事

#### 变量命名
除大写专有名词外，变量都应使用小写，[下划线命名法](#下划线命名法)。  
*常见命名*：  
- 阈值： `xxx_threshold` or `xxx_tolerance`
- 计数器： `xxx_cnt` or `xxx_count`
- 参考系： `xxx_in_world` 
  in后面接参考系，如`world`,`odom`等
- 数量： `xxx_num`

*涉及变量类型的*：  
- 指针类型： 需要为变量加前缀`p_`或者后缀`_ptr`以表示指针变量，如`img_ptr`
- 函数变量： 有时你可能会遇见匿名函数或者闭包作为变量，前面可以加上`func`

#### 成员变量命名
遵循变量命名，此外需要加上后缀`_`用于分辨成员
```cpp
class Person
{
private:
    int age_;
    double height_;
    std::string identity_;
    ...
}
```

#### 常量命名
这里常量包括宏定义、常量`const`和枚举  
统一使用大写字母，单词与单词之间使用下划线`_`分割  
不过你都写Cpp了，除去进制转换这类，我是不太推荐用宏定义了，**常量统一使用`const`**     

*示例*:  
```cpp
#define DEG2RAD(x) (x * 3.1415926 / 180)
const double HEIGHT = 1.8;
```

如果是枚举，最好在枚举变量名前面加上枚举名表示所属枚举范围  
```cpp
enum State
{
    STATE_RUN,
    STATE_IDLE
}
```

#### 函数命名
统一小写字母，[下划线命名法](#下划线命名法)，动宾组合，表示一种方法、一个动作
*示例*：  
```cpp
void preprocess();
void infer();
void postprocess();
...
void Armor::set_priority(ArmorPriority priority);
```

#### 类型命名
包含类、结构体、枚举，[驼峰命名法](#驼峰命名法)  
*示例*：
```cpp
class KalmanFilter {...};
class TrajectoryPlanner {...};
class Detector {...};
```

#### 命名空间命名
统一使用小写字母，[下划线命名法](#下划线命名法)
```cpp
namespace auto_aim
{
    ...
}

namespace volleyball
{
    ...
}
```

#### 文件命名
统一小写字母，[下划线命名法](#下划线命名法)  
*示例*：  
```bash
detector.cpp
detector_node.cpp
pnp_solver.cpp
tracker.cpp
...
```

## 注释规范
### Doxygen注释模板生成
推荐拓展插件里有，vscode上搜索`Doxygen`安装下载量最高的。  
你所需要做的就是在函数实现代码前面敲上`/**`，然后就会自动补全出一套模板，你只需要根据情况补全`@brief` `@attension`等即可。  
*示例：*
```cpp
/**
 * @brief 图像推理前的预处理
 * @param img 
 * 
 * @attention 无
 */
void Detector::preprocessing(const cv::Mat& img)
```
你甚至可以在文件开头使用相同操作自动添加以下注释模板，随后就可以自己修改了。  
```cpp
/**
 * @file detector.cpp
 * @author your name (you@domain.com)
 * @brief 
 * @version 0.1
 * @date 2026-07-28
 * 
 * @copyright Copyright (c) 2026
 * 
 */
```
### 其他场合
其他场合你可以根据步骤、变量含义、方法原理适当添加注释，不必太多也不能太少。

## git规范
每当一个开发阶段结束，代码可以正常运行而不出错误时，就应当对代码进行一次提交，并认真填写更新内容。**小步提交，分支上的每一个提交节点都是开发进入死胡同时为自己提前预留的退路**

### 分支命名
常规分支命名有以下：
- `main/master` 仓库主分支，除非开发分支`develop`测试稳定上线了，否则一般不动  
- `develop`  平时主要开发分支，由此可以向外延伸各功能开发分支
- `feature` 功能分支，每个分支负责独立子模块开发以及测试  
- `test`  测试分支
- `release`  发行分支，不过我们并不是做软件工程并不需要实际发行
- `hotfix` 赛前紧急修bug分支，修完后经审核合并回`develop`或`master`

平时大家个人开发主要是`master`与`develop`分支居多，多人协作开发的情况下，每个部分可以一个`develop`分支，比如`dev/auto_aim`,`dev/nav`。  
开发独立功能时可以在 `develop`分支新建`feature/(功能)`进行独立隔离，等开发完毕时再merge合并回`develop`分支会是一个很好的选择  
比如：  
`feature/xxx`这里`/`后简短的写入功能英文名即可。
`test/xxx`就是在测试什么功能，在调什么参数  

不过这可能会有些繁琐，也可以一个`develop`走到黑。但勤提交git一定是个好习惯，方便回档。

### 拉取与合并
开发开始前，养成**先拉取**当前所在分支的习惯.例如  
```bash
git pull origin develop
```
如果出现冲突，不要直接覆盖别人的。找出冲突文件，和管理员协调合并

### commit内容规范
每次`git commit -m ""`时内容一定包含所做事情。  
句首可以加个前缀：
- `feat：` feature缩写，告诉别人你开发了一个什么功能
- `tune:` 调参，告诉别人你调了哪一个参数
- `doc:` 写文档，告诉别人你写了一个哪方面的文档

*示例*：
```bash
git commit -m "feature:开发了识别功能"
```

**feat\tune这种排面活可以少写，但一定要清晰的表达自己开发了什么功能，调了哪个重要参数**。

### .gitignore
这个文件一定要有并且根据你的项目增加忽略上传的文件。有以下文件是必须加进这个文件的：
- 编译产物（build install之类的文件夹）
- 占用内存很大的模型文件（无论是神经网络模型还是用于碰撞检测的机械模型）
- 录像、记录图片、ros录包
- 缓存文件

## 关于CMake
### 我们目前使用C++17
请在开头`project()`后添加以下语句
```CMake
set(CMAKE_CXX_STANDARD 17)
```
### 如何拥有补全变量、函数
添加以下语句
```CMake
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)
```
之后在`.vscode/c_cpp_properties.json`文件中添加`compile_commands.json`相关路径
```JSON
"compileCommands": "${workspaceFolder}/build/compile_commands.json"
```

## 后注
### 下划线命名法
单词与单词之间使用一个下划线`_`间隔，例如`detect_cnt` `color_threshold` `ypr_in_world`

### 驼峰命名法
每个单词首字母大写其余小写，例如`AddWeight` `GetValue` `SolvePnP`。对于首字母缩写的单词, 更倾向于将它们视作一个单词进行首字母大写,例如, 写作`StartRpc()`而非`StartRPC()`.
