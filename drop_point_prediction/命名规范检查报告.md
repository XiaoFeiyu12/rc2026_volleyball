# 代码命名规范检查报告

- 依据规范：《浮舟湿地算法组开发规范.md》——「命名规范」章节
- 检查范围：`src/` 下全部 C++ 源文件、消息接口 `.msg` 文件
- 检查重点：变量命名、成员变量命名、常量/枚举命名、函数命名、类型命名、命名空间命名、文件命名
- 检查时间：2026-08-15

> 本报告只列**命名**相关问题，不包含格式排版（大括号、缩进、空格）——格式已由 `.clang-format` 统一管理。

---

## 一、总体结论

代码整体命名风格**不统一**，与规范存在系统性偏差，主要集中在四类高频问题：

1. **函数名大量使用驼峰**（应为小写蛇形）——违反规则 4，最高频、影响最广。
2. **结构体/类成员变量普遍缺少尾下划线 `_`**——违反规则 2。
3. **单字母变量泛滥**（`x/y/z`、`k/m/g`、`S/K/F/Q/P` 等）——违反规则 1，多集中在滤波器/数学代码。
4. **类型名不规范**（`robotMsg`、`planMsg`、`robotArray`、`serial_driver_node`、`EKF`、`UKF`、`_box_`、`_ball_` 等）——违反规则 5。

| 规则 | 问题数量（约） | 说明 |
|---|---|---|
| 规则 4 函数命名 | 60+ | 驼峰命名、大小写混用、非动宾 |
| 规则 2 成员变量 | 50+ | 缺尾下划线、小驼峰 |
| 规则 1 变量命名 | 80+ | 单字母、驼峰、非常规缩写 |
| 规则 5 类型命名 | 15 | 下划线/小驼峰/全大写缩写 |
| 规则 3 常量/枚举 | 15 | const 未大写、枚举值缺前缀 |
| 规则 7 文件命名 | 2 | `KF.hpp`、`KF.cpp` |

> 注：单字母数学符号（`S`、`K`、`F`、`Q`、`x`、`z` 等）在滤波器/坐标代码中大量出现，属数学惯用记法，已按规则 1 列为**低**严重度。若团队认可滤波公式符号可豁免，可整体降级处理，见第四节建议。

## 四、共性问题与整改建议

1. **函数名统一小写蛇形（最高优先）**：`PreProcessing`→`pre_processing`、`getBallPos_depth_img`→`get_ball_pos_depth_img` 这类，涉及声明+定义+调用点（含 `std::bind`）需同步改，风险在于漏改编译报错——建议用 IDE 的「重命名符号」批量改。

2. **结构体/类成员加尾下划线**：C 结构体（`detector.hpp`、`packet.h`）成员目前完全没加，属高频遗漏；改时注意同步所有读写点。

3. **枚举值加枚举名前缀**：`TO_OWN_SIDE` → `VOLLEYBALL_STATE_TO_OWN_SIDE`、`STATE_IDLE` → `TRACK_STATE_IDLE`。

4. **常量大写**：`depth_max` → `DEPTH_MAX`、`dt2` → `DT2`、`arrow_scale` → `ARROW_SCALE`；规范建议常量统一用 `const` 而非宏。

5. **单字母变量/数学符号**：滤波器（`volleyball_track`）里 `S/K/F/Q/P/x/z` 等是数学惯用记法，与规范「禁止 a/b 单字母」冲突。建议团队**明确豁免规则**：滤波/坐标公式内部允许数学符号，但成员变量、公开接口参数、业务逻辑变量必须全拼英文。否则逐条改会造成大量 diff 且降低可读性。

6. **文件命名**：`KF.hpp`/`KF.cpp` 改 `kf.hpp`/`kf.cpp`（或干脆与类型名一起改成 `kalman_filter.hpp`）。

7. **命名大小写混用**（`NMS_threshold`、`color_cameraMatrix`、`color_distCoeffs`、`depth_to_color_Rotation`、`Q_sigma_xy_min` 等）应统一为纯小写蛇形。
